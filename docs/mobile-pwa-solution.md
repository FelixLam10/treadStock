# 股势 TrendStock 多端与移动 PWA 完整方案

版本：v1.0

状态：方案设计

日期：2026-10-08

## 1. 决策摘要

TrendStock 保留现有 macOS 原生客户端，并新增以 iPhone 为第一目标设备的
Flutter Web/PWA。两端共享业务模型、分析引擎、Riverpod 状态和大部分 UI，
通过平台适配层分别接入本地存储、通知、后台任务和行情网络能力。

推荐形态：

- iPhone：Safari 打开后“添加到主屏幕”，以 standalone PWA 运行。
- Mac：继续提供 `TrendStock.app`；PWA 同时可作为免安装备用入口。
- 部署：静态 PWA + 轻量 Serverless 行情代理，不建设账号系统。
- 数据：仍以设备本地存储为主，第一期不做跨设备同步。
- 提醒：第一期仅保证打开应用时检查并展示提醒；后台推送作为独立二期。

这不是把桌面界面按比例缩小，而是把移动端作为独立使用场景设计，同时避免
维护两套产品和两套业务逻辑。

## 2. 背景与现状

### 2.1 当前已有基础

- Flutter 工程已包含 `ios/`、`macos/` 和 `web/`。
- 推荐、关注、策略、详情等核心页面已经采用单列布局，并考虑 375–428px 宽度。
- 底部三 Tab、下拉刷新、搜索、滑动操作、详情返回等交互可复用于移动端。
- 技术分析逻辑位于 Dart 层，可直接跨端复用。

### 2.2 当前 Web 阻塞项

2026-10-08 执行 `flutter build web --release`，构建失败。首要原因是：

- 数据库和 K 线缓存直接导入 `drift/native.dart`、`sqlite3` 和 `dart:ffi`。
- 数据库连接依赖 `dart:io`、`File` 和 `path_provider`。
- 通知服务直接使用 `dart:io Platform` 和原生通知插件。
- 后台任务依赖 `workmanager`，浏览器没有等价的可靠周期任务。
- 部分公开行情接口可能存在浏览器 CORS、重定向和限流差异。
- `web/index.html` 与 `manifest.json` 仍接近 Flutter 默认配置，缺少正式 PWA
  启动、更新、安装和品牌细节。

因此，移动 PWA 是一次平台能力改造，而不是单纯打开 Flutter Web 开关。

## 3. 产品目标与边界

### 3.1 目标

1. 用户无需 App Store、开发者证书或每 7 天续签，即可在 iPhone 主屏幕使用。
2. 推荐、关注、策略和个股详情在移动端具备完整主流程。
3. PWA 更新后用户无需重新安装，刷新或重启即可获得新版本。
4. 网络异常时仍可打开应用、查看本地关注和最近缓存，并明确数据时间。
5. Mac 原生端不因 Web 改造发生功能回退。

### 3.2 非目标

- 第一阶段不做账号、登录、云同步和多人共享。
- 第一阶段不承诺 PWA 在关闭后持续运行行情扫描。
- 第一阶段不承诺与原生客户端完全相同的系统通知能力。
- 不把公开行情接口的 Token 或任何未来私密密钥放进 Web 包。
- 不提供自动交易、直接买卖指令或收益保证。

### 3.3 成功标准

- iPhone Safari 首次打开可在 3 秒内展示应用壳或明确加载状态。
- 从 Safari 添加到主屏幕后，可独立全屏启动并保留关注与策略数据。
- 三个主 Tab、搜索、详情、策略编辑在 375px、390px、430px 宽度无溢出。
- PWA Release 构建通过，核心测试和 `flutter analyze` 通过。
- 行情失败、离线、无数据、无启用策略、无匹配标的五种状态可区分。

## 4. 多端产品形态

| 能力 | iPhone PWA | macOS App | 说明 |
|---|---|---|---|
| 推荐/行情 | 完整 | 完整 | 共用业务逻辑 |
| 关注列表 | 本地保存 | 本地保存 | 第一阶段互不同步 |
| 策略管理 | 完整 | 完整 | 共用模型与评分引擎 |
| 个股详情/K 线 | 完整 | 完整 | 移动端调整图表手势 |

| 跨设备同步 | 无 | 无 | 后续需账号或导入导出 |

## 5. 移动端信息架构

### 5.1 一级导航

保持底部三个主入口：`推荐`、`关注`、`策略`。

- 底部栏固定，适配 iPhone Home Indicator 安全区。
- 从其他 Tab 切回“推荐”时回到推荐首页、顶部和默认筛选。
- 再次点击当前 Tab 时回到列表顶部。
- 二级页面使用标准返回导航，不在详情页重复展示底部栏。
- 浏览器返回、边缘返回手势和页面返回按钮应得到相同结果。

### 5.2 推荐

- 首屏优先显示市场选择、更新时间、状态摘要和推荐列表。
- 市场选择使用横向分段控件：A 股、港股、美股。
- 推荐维度使用可横向滚动筛选条，保持当前“全部/波段低位/重点关注/观望”。
- 下拉刷新只触发一次请求；加载超过 1 秒显示骨架，超过超时阈值进入明确错误态。
- 卡片点击进入详情；关注操作保留独立按钮，避免整卡多重含义。

### 5.3 关注

- 搜索框点击后立即聚焦并弹出键盘。
- 搜索态占据主要内容区，右侧提供“取消”或清除按钮。
- 输入 300ms 防抖；搜索中、无结果、失败分别展示。
- 滑动删除/置顶可以保留，但必须同时提供菜单入口，避免功能只靠隐藏手势发现。
- 删除优先使用可撤销 Snackbar；不可撤销操作才弹确认框。

### 5.4 策略

- 列表先展示策略目标、状态和可理解的结果，再展示参数。
- 创建/编辑采用分组表单；数字参数使用步进器、滑块或数字键盘。
- 表单底部保存按钮避开键盘与 Home Indicator，并在提交中锁定防止重复保存。
- 明确区分：无启用策略、策略无匹配、样本不足、统计加载失败。

### 5.5 个股详情

- 顶部采用移动端标准返回按钮、标的名称、代码和复制按钮。
- K 线区域支持单指横向查看、双指缩放；页面纵向滚动与图表手势不可冲突。
- 价格、涨跌、评分、策略观察结论按阅读优先级排列。
- 复制成功使用轻提示，不使用阻断式弹窗。
- 新闻链接在 Safari 外部页面打开，并允许用户自然返回 PWA。

## 6. 移动通用交互规范

### 6.1 触控与布局

- 可点击区域最小 44×44pt，视觉图标可以更小但命中区不能缩小。
- 页面水平安全边距默认 16px；紧凑数据区可用 12px，但不可贴边。
- 固定底栏、底部 Sheet 和提交按钮必须计入 `safeArea.bottom`。
- 不依赖 hover、右键或鼠标精度；所有核心能力都必须能通过触摸发现。
- 不使用双击承担核心命令，避免与系统缩放和误触冲突。
- 横屏不作为首要布局，但不得崩溃；第一期可以提示回到竖屏而不强制锁死浏览器。

### 6.2 键盘与输入

- 搜索使用 `search` action，数字参数使用数字键盘。
- 键盘弹出时输入项和提交按钮保持可见，点击空白处收起键盘。
- 输入内容不得因页面切换或校验失败丢失。
- 中文输入法处于拼音组合阶段时，不提前发起错误搜索。

### 6.3 反馈与状态

- 轻量成功反馈使用 Snackbar/Toast；错误提示给出下一步动作。
- 骨架屏只用于首次加载；下拉刷新保留已有内容并显示轻量进度。
- 离线时展示最后更新时间，禁止把缓存数据伪装成实时数据。
- 所有金融结论继续使用“观察、线索、复盘、仅供参考”等保守措辞。

### 6.4 可访问性

- 支持系统字体放大，关键数字与按钮不截断。
- 颜色不是涨跌和状态的唯一表达，同时保留符号或文字。
- 图标按钮提供语义标签；滑动操作提供可访问的替代按钮。
- 浅色/深色模式均保证正文和涨跌信息对比度。

## 7. PWA 安装与更新体验

### 7.1 首次使用

1. 用户在 iPhone Safari 打开固定 HTTPS 地址。
2. 首次进入展示风险提示，确认后进入推荐页。
3. 非 standalone 模式下，在合适时机展示一次简短安装引导：
   “Safari 分享 → 添加到主屏幕”。
4. 已安装或用户关闭引导后不重复打扰，可在设置中再次查看安装说明。

不使用伪装成系统弹窗的大面积引导，也不在首次加载完成前打断用户。

### 7.2 启动

- `display: standalone`，竖屏优先。
- 启动画面颜色与应用主题一致，避免默认蓝色闪屏。
- 处理 iPhone 刘海、Dynamic Island 和底部 Home Indicator。
- 路由刷新后可恢复当前页面；无效深链回到推荐首页。

### 7.3 更新

- Service Worker 缓存应用壳和静态资源，不长期缓存实时行情响应。
- 检测到新版本后展示非阻断提示“发现新版本，重新加载后生效”。
- 用户确认后再刷新，避免策略编辑过程中丢失未保存内容。
- 发布异常时支持回滚到上一个静态版本。

## 8. 技术架构

```text
iPhone Safari / Installed PWA              macOS App
              |                                |
              +---------- Flutter UI ----------+
                             |
                 Riverpod / Domain / Analysis
                             |
              Repository + Platform Interfaces
                 /              |             \
        Web Persistence    Market Gateway    Native Persistence
        Drift Web/WASM     HTTPS Serverless  Drift Native/SQLite
        IndexedDB/OPFS     CORS + Cache       File + SQLite
```

### 8.1 代码分层

新增平台能力接口，业务层不直接依赖 `dart:io` 或原生插件：

- `LocalDatabaseFactory`：创建 Native 或 Web Drift 数据库。
- `NotificationService` 接口：原生实现与 Web 降级实现。
- `BackgroundTaskService`：原生注册任务；Web 实现明确返回 unsupported。
- `AppInstallService`：检测 standalone、安装引导和更新状态。
- `MarketDataTransport`：Native 直连或 Web 代理传输。

实现方式优先使用条件导入，而不是在同一文件里到处判断 `kIsWeb`。Riverpod
Provider 继续作为依赖注入入口。

### 8.2 Web 本地存储

推荐继续使用 Drift 的 Web/WASM 能力，让现有表结构、查询和 Service 最大化复用：

- Native：`NativeDatabase`。
- Web：`drift/wasm.dart`，由浏览器能力选择 OPFS 或 IndexedDB 持久化。
- SharedPreferences Web 用于风险提示、主题和轻量设置。
- 关注、策略、复盘记录和 K 线缓存仍放在结构化数据库中。

数据库初始化必须有明确失败态。Safari 清理网站数据、隐私模式或系统存储回收可能
导致本地数据丢失，产品文案不能暗示永久保存。

### 8.3 行情访问与 CORS

不建议 PWA 长期直接依赖所有第三方行情域名的 CORS 行为。推荐增加无状态、无账号的
轻量 Serverless 行情代理：

- 仅允许白名单行情端点和参数，不接受任意 URL，防止成为开放代理。
- 统一 CORS、超时、错误码和响应结构。
- 对行情快照做短时边缘缓存，K 线做更长缓存，降低限流风险。
- 不存储用户关注、策略或设备信息。
- 不放置金融服务私钥；未来需要私密 Key 时再单独评估。
- 可部署在 Cloudflare Workers 等有免费额度的平台。

Native 端第一阶段可继续直连；后续也可统一走代理以减少多端差异。

### 8.4 离线策略

- Service Worker：缓存应用壳、字体、图标和版本文件。
- Drift Web：保存关注、策略、复盘和最近行情/K 线。
- 断网启动：进入应用并展示本地数据与“离线/更新时间”提示。
- 搜索和刷新：明确提示需要网络，不清空已有结果。
- 不把过期缓存重新标记为实时数据。

### 8.5 提醒与后台能力

iPhone PWA 关闭后无法依赖 Dart 定时器或 Workmanager 持续扫描。

第一期：

- 每次启动、回到前台和用户下拉刷新时检查预警。
- 命中条件后在应用内展示提醒中心/Banner。
- 设置页明确说明“关闭应用后不会持续监控”。

可选二期：

- 使用 Web Push、Service Worker 和服务端定时任务。
- 这会引入推送订阅、设备令牌和最小服务端状态，需要单独做隐私与运维设计。
- 未完成该能力前，不展示会让用户误以为后台持续监控的开关。

### 8.6 数据同步与迁移

第一期各设备数据独立。PWA、Mac App 以及两台 iPhone 不会自动共享关注和策略。

建议在 PWA 稳定后增加“导出/导入设置”作为低成本过渡：

- 导出 JSON：关注、策略和用户设置，不包含大体积行情缓存。
- 导入前预览数量并处理重复项，不直接覆盖现有数据。
- 文件仅由用户主动保存和传输。

真正自动同步需要账号、冲突合并、加密和服务端存储，不纳入本期。

## 9. 安全与合规

- PWA 与代理必须全程 HTTPS。
- 行情代理设置域名白名单、参数校验、请求大小限制和基础限流。
- Service Worker 不缓存含敏感参数的请求，也不缓存不可控外部页面。
- 风险提示在 PWA 首次使用仍必须确认，并在推荐/详情保留免责声明。
- 不采集用户持仓、联系方式或设备标识。
- 不使用“买入、卖出、稳赚、保证”等承诺性表达。
- 若以后增加 Web Push，权限必须在用户理解用途后主动触发，不能首屏索取。

## 10. 实施阶段

### Phase 0：兼容基线与架构拆分（1–2 天）

- 建立 Web 编译门禁。
- 抽离数据库、通知、后台任务和网络平台接口。
- 保证 macOS 原生端行为不变。

验收：`flutter build web --release` 不再因 `dart:io/ffi` 导入失败。

### Phase 1：Web 数据与核心闭环（3–5 天）

- 接入 Drift Web/WASM 持久化。
- 跑通推荐、关注、策略、详情主流程。
- 实现缓存新鲜度、离线和错误状态。
- 验证 A 股、港股、美股接口在代理链路下可用。

验收：主屏安装后重启，关注和策略仍存在。

### Phase 2：iPhone 交互适配（3–5 天）

- 安全区、键盘、搜索、底栏、Sheet、表单和图表手势适配。
- 增加滑动操作的可发现替代入口。
- 完成 375/390/430px 视觉与交互检查。

验收：核心路径无溢出、遮挡、误触和键盘挡住提交按钮。

### Phase 3：PWA 安装、更新与部署（2–3 天）

- 完善 manifest、图标、启动色、Service Worker 和安装指引。
- 部署静态站点与 Serverless 行情代理。
- 增加版本更新提示、回滚和基础运行日志。

验收：微信收到链接后，可在 Safari 中添加到主屏并独立运行。

### Phase 4：质量与发布检查（2–3 天）

- 真机执行功能、离线、弱网、更新和数据保留测试。
- 回归 macOS App。
- 更新运行手册、部署说明和用户安装说明。

一期预计总工作量：约 2–3 周，取决于第三方行情源 CORS/限流与图表 Web 兼容情况。

## 11. QA 门禁

### 11.1 设备矩阵

- iPhone 小屏：375px 级别。
- iPhone 主流屏：390px 级别。
- iPhone 大屏：430px 级别。
- Safari 浏览器模式与主屏 standalone 模式。
- macOS Apple Silicon 与现有原生 App。

### 11.2 核心路径

1. 首次打开 → 风险提示 → 推荐。
2. 切换市场 → 下拉刷新 → 查看详情 → 返回。
3. 关注 → 搜索中文/代码 → 添加 → 置顶 → 删除/撤销。
4. 策略 → 创建/编辑 → 启停 → 查看统计。
5. 离线重启 → 查看缓存 → 恢复网络 → 刷新。
6. 发布新版本 → 提示更新 → 保留本地数据。
7. 从其他 Tab 返回推荐 → 回到推荐首页。

### 11.3 工程门禁

```bash
flutter analyze
flutter test
flutter build web --release --no-tree-shake-icons
flutter build macos --release
```

新增 E2E 仅用于本地临时验证，不提交测试脚本或产物。

## 12. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 第三方行情 CORS/限流变化 | Web 无法刷新 | 白名单代理、缓存、备用源、错误态 |
| Safari 清理网站数据 | 关注/策略丢失 | 明示本地存储，后续提供导出导入 |
| PWA 后台执行不可靠 | 预警延迟或缺失 | 一期只承诺前台检查，不误导用户 |
| Flutter Web 首包偏大 | 首次启动慢 | 资源精简、缓存、加载壳、性能预算 |
| 图表触摸冲突 | 页面难滚动 | 划分手势区域并做真机测试 |
| 两端实现分叉 | 维护成本上升 | Repository/平台接口隔离，共享 Domain/UI |

## 13. 推荐实施结论

建议进入实施，但按“先兼容基线，再做移动体验”的顺序推进。第一交付目标不是完整
通知能力，而是让两台 iPhone 都能通过一个 HTTPS 链接安装、稳定打开、保留本地数据，
并完成推荐—关注—详情—策略的核心闭环。

首个可用版本应包含：

- iPhone 主屏安装与独立启动。
- A/港/美股推荐和搜索。
- 本地关注、策略和缓存持久化。
- 移动端搜索、键盘、安全区、返回和触摸适配。

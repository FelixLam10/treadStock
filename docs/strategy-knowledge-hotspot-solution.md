# 策略知识沉淀、演进与热点观察方案

版本：1.1

状态：草案

日期：2026-10-08

适用版本：股势 2.1 及后续版本

实现进度（2026-10-09）：第一至第六阶段约定范围首版均已完成，候选策略版本的五类差异、冲突确认和正式启用闭环也已补齐。热点页除四入口导航、行业板块前十、双榜、默认方案、近 5 日强度、缓存和独立异常状态外，现已支持在所选行业内创建、编辑、启停、复制、恢复和版本化管理自定义筛选方案。新增热点能力采用 BaoStock 行业关系周快照、完整新浪沪深 A 股行情和本地聚合；真实网络已验证 5,223 只行情可聚合为 83 个行业。原有推荐、搜索、详情和 K 线功能保留当前数据源，不随本方案迁移。东方财富板块接口持续返回 HTTP 502 的事实继续按 `KI-DATA-001` 记录；概念板块因缺少稳定来源尚不可用。全市场/关注列表范围、策略匹配、上市天数/市值条件、自然语言条件生成，以及独立回测历史页仍作为后续增强项保留。

## 1. 决策摘要

本方案把新增需求拆成六条可独立交付、最终能形成闭环的能力：

1. 用户把书籍、市场资料、聊天文字或截图交给智能助手，智能助手去噪、脱敏并提取为“可审核的策略草稿”。
2. 通用策略和个人交易经验都保留来源、待确认项和版本历史，可持续补充，不直接覆盖旧版本。
3. 启用后的策略用于推荐筛选、个股详情解释、历史回测和运行后复盘。
4. 个股详情操作栏吸顶，搜索结果支持关注/取消关注双向切换，推荐页指标增加可解释的说明气泡。
5. 新增“热点”主入口，按板块展示当日活跃度前十及板块内候选股前十，并允许选择可计算的排名方案。
6. 所有策略输出使用“观察、信号、复盘、仅供参考”等措辞，不把来源文本中的“买入/卖出”原样升级为应用内的直接投资建议。

### 1.1 当前能力校正

仓库已经具备以下基础能力，不需要从零开始：

- 策略新增、查看、编辑、删除、启停、模板、规则型策略和加权评分策略。
- 外部大模型生成结构化数据后粘贴导入，但目前不能直接导入聊天截图或自然语言原文。
- 单策略、单股票、最多约 500 个交易日行情的基础回测，包含胜率、收益、最大回撤、盈亏比、夏普比率和交易记录。
- 策略命中记录、5 日表现回填、30 日复盘清单和历史复盘。
- 个股详情中的策略信号与解释。

当前关键缺口是：来源沉淀、版本演进、复杂多日规则表达、策略版本与回测/线上结果的关联，以及板块热点数据链路。

### 1.2 本期边界

本期建议采用“智能助手辅助 + 应用本地导入”的方式：用户在智能助手会话中提交截图或文字，智能助手生成带来源和待确认项的策略包，应用预览后导入。应用不内置大模型密钥，也不上传私人聊天记录。

本期不做：

- 应用内直接调用第三方大模型或云端文字识别服务。
- 策略市场、公开分享或他人可见的个人画像。
- 自动把含歧义的口语规则发布为启用策略。
- 把单只股票的基础回测包装成“已验证可盈利”。
- 未定义“龙头”量化口径时，由智能助手主观挑选龙头股。

## 2. 信息架构与用户闭环

原始材料（文字 / 聊天记录 / 截图）
  -> 智能助手提取、去噪、脱敏
  -> 策略草稿（规则 + 适用环境 + 风险 + 待确认项）
  -> 用户审核确认
  -> 保存为新的策略版本
  -> 回测验证
  -> 启用
  -> 推荐页 / 热点页筛选 / 个股详情策略分析
  -> 运行样本与复盘
  -> 新材料或复盘结论生成下一版本
  -> 新旧版本对比后再决定是否切换

### 2.1 策略分类

| 类型 | 命名建议 | 特点 | 默认可见范围 |
|---|---|---|---|
| 通用策略 | `五日均线趋势策略` | 来自书籍、公开资料或通用方法 | 本机私有 |
| 人物经验策略 | `{人物名} - 交易策略` | 持续补充，带明显个人习惯 | 本机私有 |
| 自定义策略 | 用户自定义名称 | 用户自行组合参数与规则 | 本机私有 |

“通用”表示来源类型，不代表策略已经由本产品验证。页面需要分别展示“来源称已验证”和“本地样本验证结果”，不能合并成一个可信度结论。

## 3. 智能助手策略沉淀规范

### 3.1 输入方式

- 纯文本：文章摘录、书摘、聊天复制文本。
- 图片：聊天截图、书页或笔记截图；由智能助手读取后生成文本摘要。
- 增量补充：为已有策略指定“补充到某人物/某策略”，生成新版本草稿。
- 多来源合并：同一策略可绑定多个来源，但必须标注规则来自哪个来源。

首期图片只在智能助手会话里解析。应用导入的是结构化策略包，不保存原始截图；如用户明确要求保留，可保存本地引用，但默认应脱敏并避免存储无关聊天内容。

### 3.2 智能助手处理顺序

1. 识别说话人、来源类型和策略主题。
2. 删除寒暄、重复、情绪化表达和与规则无关的比喻。
3. 抽取适用市场、适用趋势、观察周期、入场信号、持有条件、退出信号、过滤条件和风险提示。
4. 将每条规则标成：`明确`、`推断`、`待确认`、`当前引擎不支持`。
5. 检查规则能否由现有行情字段和指标计算。
6. 生成策略草稿、来源摘要、待确认问题和建议回测配置。
7. 用户确认后才允许保存/启用；有未解决的关键歧义时只能保存为草稿。

### 3.3 禁止行为

- 不把来源中的宣传性陈述当成历史验证证据。
- 不自行补全止盈、止损、仓位或持有天数。
- 不把“站上均线”默认解释成盘中触碰；若来源未说明，标记为“收盘价/盘中价待确认”。
- 不删除与失效场景有关的信息，例如“横盘无效”。
- 不覆盖旧策略；每次补充都创建候选版本并展示差异。
- 不把人物经验泛化为适用于所有人的通用策略。

### 3.4 策略草稿结构

| 内容 | 示例 |
|---|---|
| 策略名称 | money call - 交易策略 |
| 策略类型 | 人物经验策略 |
| 来源摘要 | 来自 money call 聊天记录，核心为趋势环境下的五日均线两日确认规则 |
| 适用市场 | 沪深股票市场 |
| 适用环境 | 上升趋势 |
| 失效环境 | 横盘震荡 |
| 入场观察规则 | 等用户确认后写入 |
| 持有观察规则 | 等用户确认后写入 |
| 退出观察规则 | 等用户确认后写入 |
| 风险说明 | 来源没有给出仓位、费用和止损细节 |
| 待确认问题 | 横盘口径、收盘价口径、第三日重新站上如何处理 |
| 引擎支持程度 | 部分支持 |
| 上一版本 | 无 |
| 当前状态 | 草稿 |

策略包必须带格式版本。导入时先校验，再进入预览页；不得直接写入启用中的策略。

## 4. 本次素材沉淀示例

### 4.1 策略草案

**名称**：`money call - 五日均线趋势策略`

**类型**：人物经验策略

**版本**：第 0.1 版草稿

**核心目标**：在明确趋势行情中，用五日均线的站上、跌破及次日确认作为观察、持有和退出信号。

**明确失效场景**：横盘震荡。

### 4.2 去噪后的明确规则

1. 前置条件：只在可识别的趋势环境中应用；横盘震荡时不应用。
2. 未站上五日均线的股票不进入观察候选。
3. 当股票首次站上五日均线，且下一个交易日未跌破五日均线，生成“入场观察信号”。
4. 持有期间只要仍在五日均线上方，保持“趋势延续”状态。
5. 当股票跌破五日均线，且下一个交易日未重新站回五日均线，生成“退出观察信号”。
6. 若站上后次日跌回，则不生成入场信号，继续观察。

### 4.3 必须向用户确认的规则

- “站上/跌破”按收盘价判断，还是盘中价格触及也算？
- 收盘价等于五日均线时算站上、站稳还是未确认？
- “横盘震荡”如何量化：指数环境、五日均线斜率、二十日/六十日均线关系、平均趋向指标，还是布林带宽度？
- “首次站上”的重置窗口是多少个交易日？
- 第一天站上、第二天跌回、第三天再站上时，是重新计为新的第一天，还是第三天即可确认？原文提出了问题但没有给出答案。
- 是否限定上升趋势，还是下降趋势反弹也适用？
- 股票池是否排除风险警示类股票、新股、停牌、涨跌停和低流动性标的？
- 是否需要仓位、滑点、手续费、止损和止盈规则？

在这些问题确认前，该策略可以用于解释和观察，但不能被标记为“规则完整”或用于正式对比结论。

### 4.4 规则引擎首版实现与边界

第三阶段已补齐：

- 价格与短期/长期均线的上方、下方及穿越关系。
- 连续若干交易日确认，不按自然日计数。
- 穿越后的等待确认、触发、失效和等待重新触发状态。
- 上涨、下跌、横盘和非横盘环境过滤。
- 推荐、个股详情和回测共用统一策略求值入口。

首版明确采用以下语义：收盘价等于均线时为中性；确认失败后需先回到另一侧并再次穿越才开启新窗口；趋势环境暂由单只股票短期均线斜率和收盘位置判断，并不等同于指数或全市场环境。指数级环境、更多横盘口径和可配置重置窗口留待后续版本。

## 5. 策略版本与持续演进

### 5.1 版本规则

- 策略是稳定身份，策略版本是不可变快照。
- 新聊天记录、新书摘或新复盘结论只能生成候选版本。
- 候选版本展示“新增、删除、修改、冲突、待确认”五类差异。
- 启用新版本前建议完成最低回测门槛；切换后保留旧版本及其历史结果。
- 命中记录、回测报告和复盘必须绑定具体策略版本，否则参数改变后历史数据会被错误归因。

### 5.2 冲突处理

同一人物在不同时间给出冲突规则时，智能助手不覆盖旧规则，而是：

1. 标出冲突的原文和日期。
2. 生成两种候选解释，或要求用户选择。
3. 保存用户裁决及原因。
4. 新版本生效后，旧版本仍可回看和回测。

首版已落地：版本页展示新增、删除、修改、冲突和待确认五类差异；有待确认项或引擎阻塞项时禁止启用，检测到相反规则时必须二次确认。启用时在同一本地事务内归档原活跃版本并更新当前策略快照，不删除旧版本及其回测记录。任一版本都可直接带入回测配置页。

### 5.3 建议数据模型

| 数据对象 | 主要内容 | 用途 |
|---|---|---|
| 策略来源 | 策略、来源类型、说话人、采集时间、脱敏文本、去重指纹 | 保存脱敏后的来源证据并避免重复导入 |
| 策略版本 | 策略、版本号、状态、规则、待确认项、上一版本、创建时间 | 保存不可变策略快照 |
| 来源与规则关系 | 来源、版本、规则清单 | 追踪每条规则的来源 |
| 回测记录 | 版本、股票范围、时间范围、配置、结果、数据截止时间 | 固化回测条件和结果 |
| 版本复盘关系 | 版本、复盘、采用决定、备注 | 绑定线上复盘与版本决策 |

原始聊天图片默认不进入数据库；脱敏文本只保存与策略有关的内容。

## 6. 个股详情中的策略分析

个股详情新增“策略分析”区域，按启用策略逐条展示：

- 当前结论：`符合`、`接近`、`不符合`、`数据不足`、`计算失败`。
- 规则进度：例如“第 1 日站上五日均线，等待下一交易日确认”。
- 命中的规则和未命中的规则。
- 当前策略版本及最后更新时间。
- 适用环境校验：例如“当前环境判定为震荡，此策略暂停给出信号”。
- 样本可信度：无样本、样本不足、已有可复盘样本。
- 操作入口：查看策略、用当前股票回测、加入关注。

必须区分以下状态：

1. 没有启用策略。
2. 有策略，但该股票没有匹配。
3. 策略匹配，但历史复盘样本不足。
4. 行情、日线或策略计算真实错误。

“不匹配”不能显示成“系统异常”，“样本不足”也不能显示成“命中率 0%”。

## 7. 回测与复盘增强

### 7.1 现状

目前已有单策略、单股票的历史回测入口和结果页，不是完全没有回测。现有回测已考虑佣金、印花税、可选滑点、仓位、止损、止盈与部分规则信号，但页面暂未把全部配置开放给用户。

### 7.2 本期增强

- 每次回测绑定不可变的策略版本。
- 展示数据区间、数据截止时间、复权方式、费用、滑点和样本数。
- 支持从个股详情直接发起“当前股票 + 当前策略版本”的回测。
- 支持同一股票比较当前版本与下一版本，至少展示胜率、总收益、最大回撤、交易次数和盈亏比。
- 回测结果可生成复盘记录，但不能自动启用策略。
- 样本过少时明确显示“样本不足”，不输出优劣结论。

### 7.3 后续增强

- 股票池/全市场横截面回测。
- 滚动窗口或样本外验证，降低过拟合风险。
- 组合级资金占用、同时持仓、涨跌停不可成交、停牌和流动性约束。
- 回测结果版本对比趋势图。

## 8. 交互增补

### 8.1 个股详情操作栏吸顶

仅将“返回、关注/取消关注、下跌预警”这一行固定在顶部；股票名称、价格、日线图和其他内容继续滚动。

建议使用可固定的滚动标题栏实现。吸顶栏需要安全区、浅色/深色背景、底部分隔线和 44 像素最小点击区域。滚动后仍能看到当前关注与预警状态。

验收：

- 任意滚动位置均可返回、切换关注和切换预警。
- 未关注时尝试开启预警，仍提示先关注；关注后可正常开启。
- 页面加载、错误或无日线数据时操作栏不消失。

### 8.2 搜索结果关注双向切换

搜索结果右侧操作按钮使用同一位置切换：

- 未关注：显示“关注”，点击后立即进入处理中状态，成功后显示“已关注”。
- 已关注：再次点击执行取消关注，成功后显示“关注”。
- 取消关注后通过轻提示提供短时“撤销”，降低误触成本。
- 网络搜索状态不影响本地关注删除；本地数据库失败时回滚按钮状态。

整行若未来用于进入个股详情，应只让右侧按钮切换关注，避免一个点击区域承载两个含义。

### 8.3 推荐页指标说明气泡

桌面端支持鼠标悬停，移动端支持长按或点击信息图标。建议文案：

| 指标 | 说明文案 |
|---|---|
| 启用策略 | `当前参与推荐计算的策略数 / 策略库总数。停用策略不会参与筛选。` |
| 平均命中率 | `启用策略中已有有效 5 日复盘样本的策略命中率平均值；样本不足时显示 --。仅供复盘参考。` |
| 市场情绪 | `根据全市场涨跌家数、指数趋势与量能环境综合判断为强势、中性或谨慎；数据不足时显示暂无。仅供环境观察。` |

当前代码里的“市场情绪”实际上由推荐数量和高分推荐数量推导。上线上述文案前必须二选一：

1. 推荐方案：接入已有的全市场环境计算结果，保留“市场情绪”名称。
2. 低成本方案：保留现有算法，但把名称改成“策略信号热度”，说明气泡明确其依据是当日策略信号数量。

不能保留现有算法却使用“全市场情绪”的解释。

## 9. 热点页

### 9.1 页面定位

新增底部主入口“热点”，与“推荐、关注、策略”并列。它回答两个问题：

1. 今天哪些板块交易最活跃或出现明显异常？
2. 进入某板块后，哪些股票最符合用户选择的可计算条件？

### 9.2 龙头股与热点股的区别

| 类型 | 要回答的问题 | 主要关注点 | 结果特点 |
|---|---|---|---|
| 龙头股 | 谁在板块内具有更强的成交影响力、相对强度和持续性？ | 成交额、板块内排名、相对板块强度、活跃持续天数 | 更强调板块地位与持续性 |
| 热点股 | 谁在当天出现明显放量、换手、振幅或价格异动？ | 量比、换手率、成交额、振幅、当日涨跌幅 | 更强调当日异常，可能持续时间较短 |

两类名单可以重叠，但不能混成一个榜单。页面默认展示“龙头股”和“热点股”两个切换项，并在榜单顶部说明当前使用的筛选方案。页面同时注明：这里的“龙头股、热点股”均为按当前条件筛选出的观察名单，不是市场公认结论。

### 9.3 页面结构

- 数据时间、盘中或收盘状态、缓存提示。
- 板块类型：行业板块、概念板块。
- 板块榜单：当日成交额、涨跌幅、换手率或量能异动前十。
- 股票类型：龙头股、热点股。
- 筛选方案：系统默认、我的方案。
- 选中板块后的股票前十。
- 每只股票展示：命中条件、未命中条件、主要排序原因、数据时间和策略匹配标签。

### 9.4 系统默认筛选方案

#### 9.4.1 公共基础过滤

两套默认方案都先执行以下过滤：

- 只保留正常交易的沪深市场股票。
- 默认排除风险警示类、退市整理、停牌和关键行情字段缺失的股票。
- 默认排除上市不足 60 个交易日的新股，用户可以关闭此条件。
- 必须属于当前选中的行业或概念板块。
- 成交额必须大于零，避免无有效交易的股票进入排名。

#### 9.4.2 默认龙头观察方案

先筛选，再计算“龙头观察分”，默认取板块内前十：

| 条件 | 默认值 | 用途 |
|---|---:|---|
| 板块内成交额排名 | 前 30% | 过滤成交影响力较弱的股票 |
| 换手率 | 2% 至 25% | 过滤流动性过低或极端换手 |
| 量比 | 不低于 1.2 | 判断当日量能不弱于近期常态 |
| 近 5 日相对板块强度 | 大于 0 | 要求走势强于所属板块 |
| 近 5 日有效交易天数 | 不少于 4 天 | 降低停牌或数据缺失影响 |

默认龙头观察分：

- 板块内成交额百分位，占 30%。
- 近 5 日相对板块强度，占 25%。
- 近 5 日成交活跃持续性，占 15%。
- 换手率百分位，占 15%。
- 当日涨跌幅百分位，占 10%。
- 已启用策略匹配分，占 5%。

该结果表示“在当前规则下更接近板块龙头特征”，不表示官方认定的龙头，也不构成操作建议。

#### 9.4.3 默认热点观察方案

先寻找当日异常活跃，再计算“热点观察分”，默认取板块内前十：

| 条件 | 默认值 | 用途 |
|---|---:|---|
| 板块内成交额排名 | 前 40% | 排除成交过于稀疏的股票 |
| 量比 | 不低于 1.5 | 识别相对近期明显放量 |
| 换手率 | 不低于 3% | 识别当日交易活跃度 |
| 振幅 | 不低于 3% | 识别盘中价格异动 |
| 行情完整性 | 价格、成交量、成交额均有效 | 避免异常数据误判 |

默认热点观察分：

- 量比百分位，占 30%。
- 换手率百分位，占 25%。
- 板块内成交额百分位，占 20%。
- 当日振幅百分位，占 15%。
- 当日涨跌幅绝对值百分位，占 10%。

热点可以是向上异动，也可以是向下异动。结果必须增加“上涨异动、下跌异动、冲高回落”等方向标签，不能把所有热点都解释成利好。

默认阈值是首版产品参数，必须通过真实市场数据观察覆盖率；若每天结果过多或长期为空，再根据复盘调整，不能把默认值描述成经过收益验证的标准。

### 9.5 用户自定义筛选

用户可复制系统默认方案后修改，也可以从空白方案创建。筛选器按以下顺序配置：

1. 选择目标：龙头观察或热点观察。
2. 选择股票范围：全市场、行业板块、概念板块或关注列表。
3. 设置排除条件：风险警示类股票、新股、停牌、涨跌停、价格范围、市值范围。
4. 添加筛选条件：选择指标、比较方式、阈值和观察周期。
5. 选择条件关系：全部满足，或任意一组满足。
6. 设置排序指标与权重。
7. 设置返回数量：前 5、前 10、前 20 或自定义。
8. 预览预计命中数量，确认后保存为“我的筛选方案”。

自定义方案必须支持：重命名、复制、启用、停用、恢复系统默认、查看最近一次运行结果和查看版本变更。智能助手也可以把用户提供的自然语言条件整理成筛选草稿，但仍需用户确认后生效。

每个筛选方案需要保存以下内容：方案名称、龙头股或热点股类型、股票范围、排除条件、筛选条件、条件关系、排序指标、排序权重、返回数量、创建时间、更新时间和方案版本。系统默认方案只读；用户修改时实际创建一份副本，后续系统升级不会覆盖用户方案。

### 9.6 市场常见筛选项

| 分类 | 常见筛选项 | 当前实现建议 |
|---|---|---|
| 股票范围 | 沪市、深市、创业板、科创板、行业、概念、关注列表 | 可直接支持 |
| 基础排除 | 风险警示类股票、退市整理、停牌、新股、涨跌停 | 大部分可支持；上市天数需要补充基础资料 |
| 价格与规模 | 最新价、流通市值、总市值 | 价格和总市值可支持；流通市值需确认接口字段 |
| 当日表现 | 涨跌幅、振幅、最高价、最低价、开盘价 | 可直接支持 |
| 交易活跃度 | 成交量、成交额、换手率、量比 | 可直接支持或本地计算 |
| 量能变化 | 今日量相对 5 日、10 日、20 日均量 | 通过历史日线本地计算 |
| 趋势强度 | 近 5 日、10 日、20 日涨跌幅，均线位置，多头排列 | 通过历史日线本地计算 |
| 相对强度 | 个股相对所属板块、相对大盘的强弱 | 需要板块和指数同期数据 |
| 价格位置 | 距离近期新高、新低、阶段回撤 | 通过历史日线本地计算 |
| 活跃持续性 | 连续放量天数、连续高换手天数、连续上涨或下跌天数 | 通过历史日线本地计算 |
| 技术指标 | 布林带位置、相对强弱指标、指数平滑异同移动平均线、随机指标 | 复用现有指标计算能力 |
| 策略条件 | 匹配指定策略、命中规则数量、策略评分 | 复用策略库 |
| 资金类数据 | 主力净流入、超大单净额、封单金额 | 需要新增并验证数据源，首期不默认开放 |
| 事件与热度 | 新闻数量、公告事件、社交讨论热度 | 需要新增数据源，首期不默认开放 |

界面默认只展示最常用的八项：成交额、成交量、换手率、量比、涨跌幅、振幅、近 5 日涨跌幅、策略匹配。其余条件放在“更多条件”中，避免第一次使用时过于复杂。

### 9.7 数据与可行性

行业热点首版采用“行业关系快照 + 全量实时行情 + 本地聚合”，只影响新增热点模块：

- BaoStock 行业关系周快照，随包发布并支持脚本更新。
- 新浪沪深 A 股全量分页行情，用于生成行业板块与成分股快照。
- 按成交额、成交量、换手率等条件执行本地筛选和排名。
- 为量能异常、相对强度和持续性读取热点专用新浪历史日线，并设置并发与缓存上限。
- 保存系统默认方案和用户自定义方案。
- 板块和成分股缓存，接口失败时展示上次更新时间。

公开接口可能限频或不稳定。行业热点只有在行业关系与实时行情至少匹配 1,000 只股票时才生成榜单，并保留七天最后有效缓存。2026-10-09 真实网络验证得到 5,223 只行情和 83 个行业板块。东方财富板块及成分股接口持续返回 HTTP 502 的问题仍按 [KI-DATA-001](known-issues.md#ki-data-001东方财富板块及成分股数据源不可用) 记录，但不再阻塞行业热点；概念板块仍需新的稳定数据源，不能用行业分类冒充。

### 9.8 加载与异常状态

- 板块加载中：展示板块前十骨架屏。
- 有缓存但刷新失败：保留缓存并显示时间提示条。
- 板块存在但无成分股：显示“暂无成分股数据”，不等同于无热点。
- 排名指标缺字段：禁用该指标并说明数据源暂不支持。
- 自定义条件不完整：保存为草稿，不运行筛选。
- 自定义条件组合后没有结果：显示“当前条件下无匹配股票”，并提供放宽条件建议。
- 非交易日：显示最近交易日数据并明确日期。

## 10. 路由与导航建议

底部导航包含“推荐、热点、关注、策略”四个入口。

二级页面包含：板块详情、筛选方案编辑、策略导入预览、策略来源与版本历史、策略版本详情、策略版本回测。

四个底部入口在小屏仍可接受，但需要在 375 像素宽度验证标签与点击区域；若后续继续增加入口，应改用“更多”而不是无限扩展底部入口。

## 11. 交付阶段与优先级

### 第一阶段：快速交互修复（必须）

- 个股详情操作栏吸顶。
- 搜索结果关注/取消关注双向切换与撤销。
- 三个指标说明气泡；同步纠正“市场情绪”算法或名称。

### 第二阶段：可追溯策略导入（必须）

- 智能助手策略包格式、导入预览和校验。
- 来源摘要、待确认项、兼容性提示。
- 策略版本表及不可变快照。
- 用本次五日均线素材做第一条验收样例。

### 第三阶段：规则表达与策略应用（必须）

- 多日确认、价格相对均线、市场环境过滤和规则状态机。
- 个股详情展示每个启用策略的规则进度和版本。
- 推荐筛选与个股详情使用同一规则执行结果。

### 第四阶段：版本化回测与复盘（应该）

- 回测结果绑定策略版本。（首版已完成）
- 个股详情一键带入回测。（首版已完成）
- 新旧版本对比与样本不足提示。（首版已完成）
- 独立历史报告列表与任意报告手动比较。（后续增强）

### 第五阶段：热点页首版（应该）

- 行业板块前十。（首版已完成）；概念板块保留入口但待稳定数据源。
- 系统默认的龙头股、热点股筛选方案。（首版已完成）
- 板块可按成交额、成交量、换手率、涨跌幅、量能异动排序，板块内输出候选前十。（首版已完成）
- 七天最后有效快照、非交易日提示和接口失败降级。（代码已完成；真实接口验收待目标网络复测）

### 第六阶段：热点自定义筛选（可以）

- 用户复制默认方案或从空白创建，修改条件、分组逻辑、权重方向、排序和返回数量。（当前板块首版已完成）
- 成交量、成交额、换手率、量比、涨跌幅、振幅、近 5 日涨跌幅和相对板块强度。（首版已完成）
- 保存草稿、启停、复制、重命名、恢复默认、最近运行结果和本地版本历史。（首版已完成）
- 全市场/关注列表范围、用户自定义公式、上市天数/市值和策略匹配。（后续增强）

### 第七阶段：候选版本治理（已完成）

- 按前一版本展示新增、删除、修改、冲突和待确认差异。
- 阻塞待确认项或不兼容规则直接禁止启用；相反规则需用户明确二次确认。
- 正式启用后保留旧版本、回测和复盘归属，并支持从任一版本进入回测。

## 12. 验收标准

### 12.1 策略沉淀

- 同一份聊天记录中的重复、寒暄和比喻不进入可执行规则。
- 每条可执行规则能追溯到来源摘要。
- 原文没有定义的关键条件全部进入待确认列表。
- 有关键待确认项或引擎不支持项时，策略不能直接启用。
- 增量材料生成新版本，不改变旧版本及其历史回测/复盘结果。

### 12.2 策略应用与回测

- 推荐、个股详情和回测对同一策略版本使用同一规则引擎。
- 无策略、无匹配、样本不足和计算失败有不同页面状态。
- 回测报告显示策略版本、数据区间、费用、滑点、样本数和数据时间。
- 相同输入数据与配置产生确定性一致结果。

### 12.3 热点页

- 用户可在板块成交额、成交量等指标间切换并看到排序依据。
- 板块前十与板块内股票前十均显示数据时间。
- 系统默认提供龙头股和热点股两套筛选方案，并展示完整条件和权重。
- 用户可以复制默认方案，修改筛选条件、逻辑关系、排序权重和返回数量。
- 默认方案升级时，不自动覆盖用户复制出的自定义方案。
- 使用“交易频繁”时明确是否为换手率近似。
- 每只股票显示进入榜单的主要原因和未满足的关键条件。
- 接口失败但有缓存时不清空页面；无缓存时给出可重试错误态。

## 13. 测试与质量门槛

- 领域单元测试：聊天去噪后的结构校验、版本差异、规则兼容性、多日确认状态机、横盘过滤、热点排名、百分位和自定义权重。
- 服务测试：策略来源与版本迁移、导入事务、回测绑定版本、板块缓存和失败降级。
- 状态管理测试：四种策略状态、关注切换回滚、热点指标切换。
- 页面与交互验证：吸顶栏、说明气泡、搜索双向切换和热点小屏布局。
- 端到端测试只用于智能助手临时自验，脚本与产物放在仓库外，不提交。
- 共享领域逻辑或数据库迁移完成后运行静态分析与全部测试。

## 14. 安全、隐私与合规

- 聊天记录可能包含姓名、头像、群名、手机号或其他个人信息；智能助手在沉淀前默认脱敏。
- 未经明确要求不保存原始截图，只保存与策略有关的脱敏摘要和来源哈希。
- 所有策略、来源、版本和回测结果继续保存在本机结构化数据库中。
- 不在客户端加入大模型接口密钥；若未来需要应用内自动解析，必须通过受控后端代理或明确选择本地模型。
- 页面持续显示“仅供观察与复盘参考，不构成投资建议”。
- “已验证策略”需要拆成来源声明、本地回测状态和真实运行样本三项，不能使用一个模糊徽章代替。

## 15. 仍需产品确认的问题

1. 五日均线策略中“站上/跌破”是否统一按收盘价判断？
2. “横盘”希望用哪种可计算定义？建议先用指数环境加五日均线斜率的组合。
3. 第一天站上、第二天跌回、第三天再站上的处理规则是什么？
4. 默认龙头股方案中的换手率上限是否保留 25%，还是允许极端活跃股票进入？
5. 默认热点股方案是否同时展示向上异动和向下异动，还是默认只看向上异动？
6. 个人交易经验策略是否默认用人物名命名，还是允许用户设置匿名别名？
